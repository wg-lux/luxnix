# Secrets Stick

The secrets stick is a USB device that is the **root of trust** for the LX
infrastructure.  Two stick modes exist:

| Mode | Who has it | Contains |
|---|---|---|
| **admin** | Infrastructure administrator | All SSH identities, all certificates, can deploy vault secrets |
| **user** | Individual developer/user | Their own SSH key and password only |

The Luxnix vault (`~/.lxv/`) manages auto-generated secrets (service
passwords, PSKs).  The stick provides the externally-sourced material that
the vault cannot generate: identities, SSL certs, and OpenVPN material.

---

## Stick directory layout

**Admin stick:**
```
<stick>/
├── .stick-meta.yml               # mode: admin, uuid, created
├── identities/
│   ├── users/
│   │   └── <username>/
│   │       ├── id_ed25519        # SSH private key     (0600)
│   │       ├── id_ed25519.pub    # SSH public key      (0644)
│   │       └── secrets/
│   │           ├── password      # plaintext password  (0600, NEVER sync)
│   │           └── password.hash # sha512crypt hash    (0644, safe to sync)
│   └── hosts/
│       └── <hostname>/
│           ├── ssh_host_ed25519_key      (0600)
│           └── ssh_host_ed25519_key.pub  (0644)
├── certificates/
│   ├── ssl/<domain>/fullchain.pem + privkey.pem
│   └── openvpn/
│       ├── ca/ca.pem + ca.key    # CA key NEVER leaves stick unencrypted
│       ├── server/crt.crt + key.key + dh.pem
│       ├── tls.pem
│       └── clients/<hostname>/crt.crt + key.key
└── backups/<timestamp>.tar.gz
```

**Personal (user-mode) stick:**
```
<stick>/
├── .stick-meta.yml               # mode: user, owner: <username>
└── identities/
    └── users/
        └── <owner>/
            ├── id_ed25519[.pub]
            └── secrets/
                ├── password      # (0600, never leaves stick)
                └── password.hash # (0644, synced to inventory)
```

## Inventory integration

`ansible/inventory/group_vars/stick_pubkeys.yml` is **auto-generated** — do not
edit by hand.  It is regenerated by `identity sync-inventory` and contains:

```yaml
# AUTO-GENERATED — do not edit
authentication:
  admin:
    id_ed25519_pub: ssh-ed25519 AAAA...
    password_hash: $6$rounds=5000$salt$...
  dev_01:
    id_ed25519_pub: ssh-ed25519 AAAA...
    password_hash: $6$...
```

- **`id_ed25519_pub`** — used by NixOS ssh-access role and ansible `authorized_keys`
- **`password_hash`** — sha512crypt, used by NixOS `users.users.<name>.hashedPassword`
- Plaintext passwords are **never written** to this file or to git

---

## Environment variable

`.envrc` auto-detects a mounted stick and sets `LX_SECRETS_STICK`.
Override manually:

```bash
export LX_SECRETS_STICK=/run/media/admin/my-stick
```

# Administrator Guide

This covers managing the full network: all user identities, all certificates,
and vault secret staging.

## First-time admin stick setup

### 1 — Initialise the admin stick

```bash
lx-secrets --stick /run/media/admin/my-stick stick init
export LX_SECRETS_STICK=/run/media/admin/my-stick
```

### 2 — Generate the admin SSH identity

```bash
lx-secrets identity gen-user admin
lx-secrets user set-password --username admin --generate

# Copy the private key to ~/.ssh/ on this machine:
cp "$LX_SECRETS_STICK/identities/users/admin/id_ed25519" ~/.ssh/id_ed25519
chmod 600 ~/.ssh/id_ed25519
```

### 3 — Import OpenVPN certificates (from s-01)

```bash
# On s-01 — collect material:
tar czf /tmp/openvpn-material.tar.gz -C /etc/openvpn .

# On admin machine:
scp admin@s-01:/tmp/openvpn-material.tar.gz /tmp/
mkdir /tmp/openvpn-material
tar xzf /tmp/openvpn-material.tar.gz -C /tmp/openvpn-material

lx-secrets cert import-openvpn /tmp/openvpn-material
rm -rf /tmp/openvpn-material /tmp/openvpn-material.tar.gz
```

### 4 — Import the SSL certificate (from s-02)

```bash
scp admin@s-02:/etc/letsencrypt/live/endo-reg.net/fullchain.pem /tmp/
scp admin@s-02:/etc/letsencrypt/live/endo-reg.net/privkey.pem /tmp/

lx-secrets cert import-ssl endo-reg.net \
    /tmp/fullchain.pem /tmp/privkey.pem

rm /tmp/fullchain.pem /tmp/privkey.pem
```

### 5 — Generate identities for developers

```bash
# For each developer, either:
# (a) Generate on the admin stick directly:
lx-secrets identity gen-user dev_01
lx-secrets user set-password --username dev_01 --generate

# (b) Or import from their personal stick submission (see User Guide):
lx-secrets admin import-snippet dev_01-submission.yml
```

### 6 — Sync public keys + hashes to inventory

```bash
devenv tasks run secrets:sync-inventory
# or:
lx-secrets identity sync-inventory
```

Commit `ansible/inventory/group_vars/stick_pubkeys.yml` to git.

Then rebuild NixOS configs so ssh-access roles and user modules pick up the
new data:

```bash
devenv tasks run autoconf:finished
```

### 7 — Bootstrap the Luxnix vault

```bash
# Generate all PSKs and service passwords, export per-host archives:
uv run python scripts/bootstrap-lx-vault.py --export

# If you have admin passwords to import (including user passwords from stick):
lx-secrets vault stage-passwords \
    --output /tmp/lx-admin-passwords.yml
uv run python scripts/bootstrap-lx-vault.py \
    --admin-passwords /tmp/lx-admin-passwords.yml --export
shred -u /tmp/lx-admin-passwords.yml
```

### 8 — Stage SSL certs for vault deployment

```bash
# Stage for all hosts in the [ssl_cert] group (gc-06, s-02, s-03, h-01):
devenv tasks run secrets:stage-ssl
# or:
lx-secrets vault stage-ssl-group endo-reg.net ssl_cert

# Verify:
devenv tasks run secrets:vault-status
```

### 9 — Stage Keycloak admin bootstrap password

This stages the `keycloak_admin` password from the stick as a vault-encrypted
secret for h-01.  The NixOS keycloakHost module reads it at runtime via
`keycloak-prepare-admin-env.service` — the plaintext never enters the Nix store.

```bash
# One-shot (generates password on stick + stages for h-01):
devenv tasks run secrets:stage-keycloak-admin

# Or manually:
lx-secrets user set-password --username keycloak_admin --generate
lx-secrets vault stage-keycloak-admin --hostname h-01

# Verify the file is staged:
devenv tasks run secrets:vault-status
```

### 10 — Deploy all secrets via Ansible

```bash
ansible-playbook ansible/playbooks/deploy_secrets.yml

# Or limit to a host:
ansible-playbook ansible/playbooks/deploy_secrets.yml --limit h-01
```

### 11 — Deploy OpenVPN certs to the VPN server

```bash
lx-secrets cert deploy-openvpn --dest /tmp/vpn-stage

# Copy server certs and the full ccd directory (per-client static routes):
rsync -av -e "ssh -i ~/.ssh/ssh-hetzner-main_openssh" \
    /tmp/vpn-stage/ admin@h-01:/tmp/vpn-stage/
rsync -av -e "ssh -i ~/.ssh/ssh-hetzner-main_openssh" \
    /etc/openvpn/ccd/ admin@h-01:/tmp/vpn-ccd/

ssh -i ~/.ssh/ssh-hetzner-main_openssh admin@h-01 '
    sudo cp /tmp/vpn-stage/* /etc/openvpn/
    sudo chmod 600 /etc/openvpn/*.key /etc/openvpn/*.pem
    sudo mkdir -p /etc/openvpn/ccd
    sudo cp -r /tmp/vpn-ccd/. /etc/openvpn/ccd/
    sudo chmod 644 /etc/openvpn/ccd/*
'
rm -rf /tmp/vpn-stage
```

## Day-to-day admin operations

### Check stick status

```bash
devenv tasks run secrets:check-stick
```

### Backup stick

```bash
devenv tasks run secrets:backup-stick
```

### List all users and their data status

```bash
lx-secrets admin list-users
```

### Import a developer's personal stick submission

Developers run `user sync` on their personal stick and submit the YAML file
(e.g. via PR or secure channel).  The admin imports it:

```bash
lx-secrets admin import-snippet dev_01-submission.yml
# Re-sync inventory and rebuild:
devenv tasks run secrets:sync-inventory
devenv tasks run autoconf:finished
```

Only pubkeys and password hashes are accepted; plaintext passwords in the
snippet are silently rejected.

### Import a single pubkey

```bash
lx-secrets admin import-pubkey dev_01 \
    "ssh-ed25519 AAAA..."
devenv tasks run secrets:sync-inventory
```

### Override a user's inventory entry

Admin stick always wins: re-import the correct key/hash and re-run
`identity sync-inventory`.  The generated `stick_pubkeys.yml` is the
authoritative source — user-submitted PRs are reviewed and applied only
through `admin import-snippet`, never by direct PR merges to
`stick_pubkeys.yml`.

### Rotate a compromised key

```bash
lx-secrets identity gen-user dev_01 --force
lx-secrets user set-password --username dev_01 --generate
devenv tasks run secrets:sync-inventory
devenv tasks run autoconf:finished
# Rebuild and deploy NixOS config on affected hosts
```

### Rotate an SSL certificate (Let's Encrypt renewal)

```bash
lx-secrets cert import-ssl endo-reg.net \
    /etc/letsencrypt/live/endo-reg.net/fullchain.pem \
    /etc/letsencrypt/live/endo-reg.net/privkey.pem

devenv tasks run secrets:stage-ssl
ansible-playbook ansible/playbooks/deploy_secrets.yml --limit ssl_cert
```

### View staged vault secrets

```bash
devenv tasks run secrets:vault-status
# or for a specific host:
lx-secrets vault status h-01
```

# User Guide

This covers using a **personal (user-mode) stick** to manage your own SSH key
and password.  You do not need access to the admin stick or the full vault.

## Setting up your personal stick

### 1 — Initialise a personal stick

```bash
lx-secrets --stick /run/media/dev_01/my-stick \
    stick init --mode user --owner dev_01
export LX_SECRETS_STICK=/run/media/dev_01/my-stick
```

### 2 — Generate your SSH key

```bash
lx-secrets identity gen-user dev_01
# Install your private key locally:
cp "$LX_SECRETS_STICK/identities/users/dev_01/id_ed25519" ~/.ssh/id_ed25519
chmod 600 ~/.ssh/id_ed25519
```

### 3 — Set your password

```bash
# Prompted entry:
lx-secrets user set-password

# Or generate a random password:
lx-secrets user set-password --generate
```

Your plaintext password is stored on the stick at mode 0600.  Your
sha512crypt hash is stored at mode 0644.  Only the hash is ever shared.

### 4 — Retrieve your hash or show your password

```bash
# Safe — show the hash only:
lx-secrets user show-hash

# Show the plaintext (personal stick only, no --confirm needed):
lx-secrets user show-password
```

### 5 — Create a submission for the admin

```bash
lx-secrets user sync \
    --output dev_01-submission.yml
```

This file contains your public key and password hash — **no plaintext
password**.  Submit it to the admin (e.g. as a PR or via a secure channel).
The admin runs `admin import-snippet dev_01-submission.yml` and then
regenerates `stick_pubkeys.yml`.

### 6 — Backup your stick

```bash
lx-secrets stick backup
```

## Workflow summary

```
User (personal stick)                   Admin (admin stick)
─────────────────────                   ──────────────────
identity gen-user <me>
user set-password --generate
user sync --output my-sub.yml
          ──────────────────────────►
                                        admin import-snippet my-sub.yml
                                        identity sync-inventory
                                        autoconf:finished
                                        (stick_pubkeys.yml committed to git)
                                        deploy_secrets.yml
```

## Permissions reference

| Location | Owner | Mode | Set by |
|---|---|---|---|
| `/etc/secrets/` | `root:sensitiveServices` | `0750` | `managed-secrets` NixOS module |
| `/etc/secrets/vault/` | `root:sensitiveServices` | `0750` | `managed-secrets` NixOS module |
| `/etc/secrets/vault/ssl_cert` | `root` | `0600` | Ansible `deploy_secrets.yml` |
| `/etc/secrets/vault/ssl_key` | `root` | `0600` | Ansible `deploy_secrets.yml` |
| `/etc/secrets/vault/SCRT_*` | `root` | `0600` | Ansible `deploy_secrets.yml` |
| `/etc/secrets/.psk` | `root` | `0600` | Ansible `deploy_secrets.yml` |
| `/etc/openvpn/*.pem` | `root` | `0600` | Manual / `cert deploy-openvpn` |
| `~/.lxv/psk/*.psk` | admin | `0600` | `bootstrap-lx-vault.py` |
| Stick private keys | stick owner | `0600` | `lx-secrets identity gen-*` |
| Stick password files | stick owner | `0600` | `lx-secrets user set-password` |
| Stick password hashes | stick owner | `0644` | `lx-secrets user set-password` |

**Why nginx can read mode 0600 SSL certs:** nginx in NixOS starts as root,
reads cert files, then drops privileges.

## devenv tasks reference

| Task | What it does |
|---|---|
| `secrets:check-stick` | Verify stick is mounted and layout is complete |
| `secrets:backup-stick` | Create a timestamped backup on the stick |
| `secrets:sync-inventory` | Regenerate `stick_pubkeys.yml` from all users on stick |
| `secrets:stage-ssl` | Stage `endo-reg.net` SSL cert for all `[ssl_cert]` hosts |
| `secrets:stage-keycloak-admin` | Generate keycloak_admin password on stick and stage it for h-01 |
| `secrets:vault-status` | Show what is staged in `~/.lxv/deploy/` |
