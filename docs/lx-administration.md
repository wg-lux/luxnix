# lx-administration

`lx_administration` is the Python package that drives automated NixOS configuration generation for LuxNix. It reads the Ansible inventory, merges per-host variables, and renders Jinja2 templates into the `systems/` and `homes/` directory trees.

## Overview

```
Ansible inventory
  (hosts.ini + group_vars + host_vars + cmdb/)
              │
              ▼
       ansible_etl()
   autoconf/merged_vars/<host>.yml
              │
              ├──▶ home_etl()
              │    autoconf/home_merged_vars/<host>.yml
              │
              ▼
         nix_pipe()
   systems/<platform>/<host>/default.nix
   homes/<platform>/<user>@<host>/default.nix
```

## Running the pipeline

```bash
# via devenv task (recommended)
devenv tasks run autoconf:finished

# direct invocation
python scripts/autoconf-pipeline.py
```

Both call `lx_administration.autoconf.main.pipe()` with:

| Parameter       | Default          | Description                                       |
|-----------------|------------------|---------------------------------------------------|
| `ansible_root`  | `./ansible`      | Root of the Ansible directory                     |
| `autoconf_out`  | `./autoconf`     | Output directory for merged vars and inventory    |
| `nix_out`       | `.`              | Repository root — generated .nix files go here   |
| `conf_parent`   | `./conf`         | Parent of `nix-templates/`                        |

Pipeline logs are written to `autoconf/logs/`.

## Step 1 — Ansible ETL (`ansible_etl`)

**Source:** `lx_administration/autoconf/imports/main.py`

Reads the Ansible inventory and produces one merged YAML file per system host.

### What it does

1. Loads `ansible/inventory/hosts.ini` — all hosts and group memberships.
2. Loads host facts from `ansible/cmdb/` (generated by `scripts/ansible-cmdb.sh`).
3. For each host, merges in priority order (later wins):
   - `group_vars/all.yml` — fleet-wide defaults
   - `group_vars/<group>.yml` — per-group settings (multiple groups allowed)
   - `host_vars/<hostname>.yml` — host-specific overrides
4. Identifies **home-only hosts** (hosts in `[home_config]` but without a system configuration — these get home-manager configs only and are skipped for `systems/` generation).
5. Validates each merged dict against the `MergedHostVars` Pydantic model.
6. Writes `autoconf/merged_vars/<hostname>.yml` for each system host.
7. Writes `autoconf/inventory.yml` (full flattened inventory snapshot).

### Output

```
autoconf/
  merged_vars/
    gc-02.yml        # fully merged config for gc-02
    gs-01.yml
    s-01.yml
    ...
  inventory.yml      # snapshot of the full inventory
  logs/
    autoconf_main_pipe.log
```

## Step 2 — Home ETL (`home_etl`)

**Source:** `lx_administration/autoconf/imports/main.py`

Runs the same merge logic as `ansible_etl` but for home-manager variables, sourced from `host_vars/<hostname>/` sub-directories (the `home/` subdirectory of each host_vars folder).

Outputs to `autoconf/home_merged_vars/<hostname>.yml`.

---

## Step 3 — Nix generation (`nix_pipe`)

**Source:** `lx_administration/autoconf/nix/main.py`

For each file in `autoconf/merged_vars/`:

1. Loads the YAML into a `MergedHostVars` model.
2. Determines the host platform (e.g. `x86_64-linux`) from `generic_settings.hostPlatform`.
3. Determines the template name from the `template_name` field (default: `main`).
4. Locates the template directory:
   ```
   conf/nix-templates/systems/<platform>/<template_name>/
   ```
5. Calls `export_host_config()` on the merged vars — this produces the three dictionaries that the template receives.
6. Renders `default.nix.j2` with Jinja2.
7. Writes to `systems/<platform>/<hostname>/default.nix`.

Home configs follow the same flow using `autoconf/home_merged_vars/` and `conf/nix-templates/homes/<platform>/`.

## Template system

### Location

```
conf/nix-templates/
  systems/
    x86_64-linux/
      main/
        default.nix.j2     ← system config template
  homes/
    x86_64-linux/
      default.nix.j2       ← home-manager config template
```

### Template variables

The `default.nix.j2` for systems receives:

| Variable         | Type   | Description                                             |
|------------------|--------|---------------------------------------------------------|
| `hostname`       | string | The hostname (used in the file header comment)          |
| `role_configs`   | dict   | Key-value pairs rendered into the `roles { }` block     |
| `service_configs`| dict   | Key-value pairs rendered into the `services { }` block  |
| `luxnix_configs` | dict   | Key-value pairs rendered into the `luxnix { }` block    |

Multi-line values are wrapped in Nix multi-line strings (`''...'`); single-line values are emitted as-is.

### Generated file structure

The template always produces the same skeleton:

```nix
# <hostname>/default.nix
{ config, pkgs, lib, modulesPath, ... }:
{
  imports = [
    (modulesPath + "/installer/scan/not-detected.nix")
    ./boot-decryption-config.nix
    ./disks.nix
  ];

  user = {
    admin = { name = "admin"; };
    ansible.enable = true;
    settings.mutable = false;
  };

  roles    = { ... };   # from role_configs
  services = { ... };   # from service_configs
  luxnix   = { ... };   # from luxnix_configs
}
```

Hardware-specific files (`disks.nix`, `boot-decryption-config.nix`) are **not** generated — they are authored manually and committed alongside the generated `default.nix`.

## MergedHostVars model

**Source:** `lx_administration/models/`

Pydantic model that validates every merged host config before it reaches the template. It enforces required fields and provides `get_host_platform()` and `export_host_config()` methods used by the nix pipeline.

If validation fails, a warning is emitted but the pipeline continues, skipping the failing host.

---

## Home-only hosts

A host is treated as home-only when it appears in the `[home_config]` inventory group but has no system-level configuration worth generating (e.g. a laptop managed solely through Home Manager). Home-only hosts:

- Get `autoconf/home_merged_vars/<hostname>.yml`
- Get `homes/<platform>/<user>@<hostname>/default.nix`
- Do **not** get `systems/<platform>/<hostname>/default.nix`

## Debugging

| Problem                              | Where to look                                        |
|--------------------------------------|------------------------------------------------------|
| Pipeline errors                      | `autoconf/logs/autoconf_main_pipe.log`               |
| Merged variable output               | `autoconf/merged_vars/<hostname>.yml`                |
| Invalid merged vars warning          | Look for `Invalid merged_vars for <host>` in logs   |
| Host skipped with no platform        | Look for `Failed to get host platform` in logs      |
| Template rendering errors            | Check `conf/nix-templates/systems/…/default.nix.j2` |
| Generated file looks wrong           | Compare `autoconf/merged_vars/<host>.yml` with template |

## Adding a new host

See [ansible-workflow.md](./ansible-workflow.md) for the full workflow. In terms of the pipeline:

1. Add the host and its group memberships to `ansible/inventory/hosts.ini`.
2. Create `ansible/inventory/host_vars/<hostname>.yml` with at minimum:
   - `template_name: "main"`
   - `host_luxnix.generic_settings.hostPlatform: '"x86_64-linux"'`
   - `host_luxnix.generic_settings.systemStateVersion`
   - CPU microcode, kernel modules, and GPU settings as needed.
3. Run `devenv tasks run autoconf:finished`.
4. Verify `autoconf/merged_vars/<hostname>.yml` looks correct.
5. Verify `systems/x86_64-linux/<hostname>/default.nix` was generated.
6. Add `disks.nix` and `boot-decryption-config.nix` manually for the new host.

## Module structure reference

```
lx_administration/
  autoconf/
    main.py              # top-level pipeline orchestrator
    imports/
      main.py            # ansible_etl + home_etl
      __init__.py        # load_inventory_hostfile, load_all_host_facts
      utils.py           # is_home_only_host, load_home_host_vars
    nix/
      main.py            # nix_pipe, generate_default_nix
      template_renderer.py
      utils.py           # write_nix_file
      home.py            # home_pipe
  models/                # Pydantic models (MergedHostVars, etc.)
  vault/                 # Vault management
  password/              # Password generation and hashing
  ssh/                   # SSH key management
  yaml/                  # YAML dump helpers
  logging/               # Centralised logging (get_logger, log_heading)
```
